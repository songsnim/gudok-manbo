# 261005-feat-widget-redesign — 위젯은 홈 화면의 입간판이다

**Blocked by:** 없음 — 시안 승인됨 (2026-10-05).

**Status:** done

## What to build

위젯의 역할은 읽게 하는 게 아니라 **들어오게 하는 것**이다. 앱을 열지 않아도 홈 화면에서
"이런 글이 들어와 있어요"가 눈에 밟히고, 한 번 탭하면 그 글 본문이 바로 열린다. 피드 페이지의
위젯 버전이다.

지금 위젯은 흰 배경 + 파란 헤더라 다크 고정인 앱과 이어지지 않고, `/feed/today`만 봐서 오전
6시 수집 전엔 비어 있으며, 탭하면 앱 첫 화면만 열린다. 앱에서 읽음 처리해도 위젯은 갱신되지
않는다.

디자인은 토스풍 다크. 단 인앱 다크 토큰(배경 #121316, 표면 #1E1F22, 본문 #E3E3E5, 보조
#8A8D93, 강조 #8AB4F8)과 피드 행 구조(`FeedItemRow`)를 기준점으로 삼아, 같은 앱이라는 게
무의식적으로 느껴져야 한다. 인앱은 이 티켓에서 바꾸지 않는다.

## Acceptance criteria

- [ ] Feed(articles/)의 **안 읽은** Item을 수집 최신순으로 최대 5개 보여준다. 읽은 Item과
      Collection은 나오지 않는다.
- [ ] 헤더: 앱 아이콘 + "피드" + 미읽음 총개수.
- [ ] 각 행: 플랫폼 배지 + 채널명 + 제목 + 썸네일. 썸네일은 인앱과 같은 YouTube `hqdefault` 규칙, 없으면
      플랫폼 색·아이콘 블록으로 같은 크기를 채운다.
- [ ] 행 탭 → 그 Item 본문 화면으로 바로 열림(slug 딥링크). 본문에서 뒤로 가면 피드.
- [ ] 읽음 상태는 앱과 위젯이 같은 Room을 쓴다. 앱에서 읽음 처리하면 위젯도 즉시 갱신된다.
- [ ] 다 읽으면 빈 상태 — "다 읽었어요" + 다음 수집 시각(`/settings`의 schedule 기준).
- [ ] 기본 4×4, 크기 조절 가능. 줄이면 보이는 행 수가 줄고 레이아웃은 깨지지 않는다.
- [ ] `widgetCategory`에 `keyguard` 포함 — 삼성이 서드파티 잠금화면 위젯을 열면 바로 쓸 수 있게.
- [ ] 위젯용 목록 API는 본문(body)을 빼고 개수를 제한한다 — 위젯 갱신에 Item 전체 본문을 받지 않는다.
- [ ] 갱신: 기존 1시간 주기 + 앱 시작 + 읽음 처리 시 + 수집 시각(6·11·17시) 직후.
- [ ] 미읽음 5개 선별 로직(정렬·읽음 제외·개수 제한)을 확인하는 검사 하나.

## Out of scope

- 잠금화면 알림 — `261005-feat-new-items-notification`.
- 인앱 피드 디자인 변경.
- 위젯에서 읽음 처리·Collection 이동 — 위젯은 보여주고 들어오게만 한다. 읽음은 앱에서.
